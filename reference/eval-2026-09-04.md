# Council Seat Validation — 2026-09-04

Scope: validate the `council-architecture` seat rebalance
(`nemotron-3-ultra-free` → `muse-spark-1.2-contributor-free`, 2026-09-03).
This is a **seat validation, not the full head-to-head** (07-26 style):
it gates the seat muse-spark already holds; additional seats remain gated
on the full eval. Pre-registered prompts + checklist below; graded after
the runs, no post-hoc criteria.

## Method

Three architecture-lens prompts through `council-architecture`
(muse-spark-1.2-contributor-free, temperature 0.2), plus two
cross-family convergence runs on the same scenarios:
P2 through `council-product` (nemotron-3-ultra-free),
P1 through `council-security` (mimo-v2.5-free).

Checklist (structural, not taste-based):
(a) 3–5 bullets, concise; (b) stays in the architecture lens
(patterns, decomposition, state ownership, testability);
(c) concrete — names mechanisms/patterns, not platitudes;
(d) no refusal or degenerate output;
(e) names at least one tradeoff or risk.

## Prompts (pre-registered)

- **P1**: mobile client needs offline request queuing with replay to a REST
  API — key architecture decisions and structural risks?
- **P2**: plan puts retry-with-backoff inside each UI component's
  data-fetch hook — structural/maintainability review?
- **P3**: API response transformation lives inside view components —
  where should it live and why?

## Results — architecture seat (muse-spark)

| Criterion | P1 (offline replay) | P2 (retry in hooks) | P3 (transform in views) |
|---|---|---|---|
| (a) 3–5 concise bullets | ✓ 4 bullets | ✓ 4 bullets | ✓ preamble + 4 bullets |

| (c) concreteness | ✓ IndexedDB/localForage/idb, typed op envelope schema, syncEngine, Idempotency-Key, ETag/If-Match, FIFO blocking | ✓ interceptor/service layer, RetryPolicy schema, abort-signal, circuit breaker | ✓ services/api + lib/mappers, dto→domain, Zod, Pinia/store |
| (d) no refusal/degeneration | ✓ substantive | ✓ substantive | ✓ substantive |
| (e) tradeoff/risk named | ✓ duplicates, queue-blocking, silent loss | ✓ tech debt, leaked timers, races | ✓ contract coupling, versioning debt |

**Verdict: PASS on all pre-registered criteria, all three prompts.**

Full outputs (evidence):

P1:
> * **Persistence & state ownership:** In-memory store queue is lost on
> reload/kill — requires durable layer (IndexedDB via
> `localForage`/`idb`) separate from UI store ... typed envelope
> `{id: clientUUID, op, entity, payload, createdAt, attempt,
> idempotencyKey}` ...
> * **Decomposition & data flow:** ... single `queue` module +
> `syncEngine` ... Flow must be `action → optimistic store update +
> enqueue → syncEngine replays → confirm/rollback` ...
> * **Conflict / ordering & type safety:** ... naive FIFO blocks entire
> queue on one 4xx ... per-entity ordering not preserved ...
> * **Testability & debt:** ... no integration test for
> `offline→enqueue→online→replay→conflict` leaves the critical path
> uncovered; unbounded queue growth, no backoff/eviction, expired auth
> during replay ...

P2:
> * **Layer violation / poor decomposition:** Retry with backoff is a
> transport cross-cutting concern, not UI logic ... violates SRP ...
> * **Duplication and drift:** copying retry config per hook guarantees
> inconsistency ... no single source of truth ...
> * **Lifecycle and state misplacement:** retry timers tied to
> mount/unmount ... leaked timers, races on rapid remount ...
> * **Reduced testability and extensibility:** ... blocks auth refresh,
> circuit breaker, observability, idempotency — N component changes
> instead of one.

P3:
> * **Location: API adapter / mapper layer** (`services/api/`,
> `lib/mappers/`, pure `dto → domain`) ... view stays presentational.
> * **Data flow / state ownership:** validate + transform at boundary,
> store normalized domain model ...
> * **Schema and type safety:** DTO schema (e.g. Zod) at edge, domain
> type for app use ...
> * **Testability / debt / extensibility:** pure mappers unit-testable
> without mounting; centralization removes drift ...

## Convergence checks (cross-family)

- **P2, nemotron (product lens):** independently flags duplication across
  N hooks, wrong abstraction layer (infra vs UI), testability
  multiplication, missing central observability; adds thundering-herd
  angle. Same core verdict as muse-spark, complementary extras, no
  contradiction. ✓ convergent.
- **P1, mimo (security lens):** independently flags idempotency/duplicate
  writes, dependent-write ordering, partial-failure rollback —
  converging with the architecture output's idempotency/ordering/rollback
  points from a different lens. Adds auth-expiry, replay-DoS
  amplification, at-rest exposure, validation drift. No contradiction. ✓
  convergent. (Note: 7 sections — over the 3–5 bullet budget, but that
  budget was pre-registered for the architecture seat, not this lens.)

## Limits (read before citing this)

- Single rater, and the rater runs on a muse-spark model — same-family
  grading bias is possible; mitigated by grading structure (checklist),
  not taste. An independent-family re-grade would strengthen this.
- n=3 prompts, architecture lens only. The `council-ux` → mimo move is
  not separately evaluated here (mimo carries its prior validation; the
  lens transfer itself is untested).
- No cross-model A/B: bindings are fixed per agent file, so the same
  prompt + system prompt on nemotron was not available without
  transient agent files. Convergence runs are the substitute, not the
  equivalent.
- **This does not satisfy the "head-to-head eval" bar** in the Free-tier
  caveats for granting muse-spark *additional* seats. It validates the
  one seat it holds.

`muse-spark-1.2-contributor-free` holds the `council-architecture` seat
without observable degradation: lens-adherent, concrete, well-formed
output that converges with independent nemotron and mimo findings.
Status change: seat validated (this artifact); full head-to-head eval
