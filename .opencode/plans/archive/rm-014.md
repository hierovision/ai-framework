# Plan: rm-014

## Goal / Approach

Make self-improvement first-class for real exercises: when the framework is
exercised on a target repo, the session captures framework-improvement
candidates in a fixed-shape artifact (promoted to GitHub issues on this repo
at close) and converts its learnings into the target repo's own three-tier
memory plus a dated uplift ledger — so both repos get durably better and
the next exercise starts from the new baseline.

Approach: one contract file (`reference/self-improvement.md`, Layer 1)
defining the two artifact shapes, the capture-don't-fix rule, and the
promotion rules; skill hooks by citation only (authoring-skills re-anchors
its orphaned handoff-proposal sentence; implementing-features gains one
clause routing exercise-context skill-urges to the candidate file);
routing rows in CONTRIBUTING + the ADR index table; the decision recorded
as ADR-0010; ROADMAP RM-014 → done. No new skill, no new CI — the
mechanism is contracts + wiring; the behavioral proof comes from the
trigger-gated exercises themselves (RM-012 is its consumer).

Design decisions locked with the user (2026-09-24): the loop is two-way
(upstream candidates → framework; downstream uplift → target repo);
candidates promote to GitHub issues on `hierovision/ai-framework`
(`triaging-requirements` already consumes live GitHub issues — no new
triage surface); the uplift ledger is a working artifact, never
archive-as-memory (ADR-0008 discipline).

## Scope

**Included**

- The contract file with both artifact shapes inline (candidate + uplift
  ledger), the capture-don't-fix rule, promotion rules, and the archive
  lifecycle for the exercise file
- The three skill/doc hooks by citation (authoring-skills,
  implementing-features, CONTRIBUTING/ADR routing tables)
- ADR-0010 + ROADMAP reconciliation

**Excluded**

- A new skill owning the loop (the contract lives in `reference/`; a
  dedicated skill is RM-012's harvest-time call if the exercises prove
  one is needed — no speculative skill)
- Any behavioral eval harness for the loop (its proof is the real
  exercises; a synthetic harness would test the documentation, not the
  behavior — the honest negative is recorded here)
- Changing `install.sh`, the eval gates, the registry schema, or
  `triaging-requirements` (it already consumes GitHub issues natively)
- RM-012's execution (trigger-gated) and RM-006 templates
- Any edit to AGENTS.md standing rules (the capture rule is already
  expressed in authoring-skills; the contract file is the authority)

## Schema / Type Impacts

None (no DB, no generated types). New artifact contracts defined in
`reference/self-improvement.md`: the candidate block and the uplift
ledger entry. Both are working artifacts in the target repo
(`.opencode/exercise.md` until close), versioned there per ADR-0008's
plan-lifecycle rule (essence extracted → archived).

## Open Questions

- **Candidate issue label** — default `skill-improvement` (triage reads
  the issues regardless; the label is for human filtering).
- **Exercise file name** — default `<target-repo>/.opencode/exercise.md`
  (one file per repo, append-only ledger + candidates; archived at
  close). Alternative: one file per exercise — rejected as noise for a
  standing relationship with a repo.
- **Who writes the target repo's AGENTS.md** — default: the exercise
  session itself, at close, from the uplift ledger (cross-session
  imperatives only, per the AGENTS.md discipline).
