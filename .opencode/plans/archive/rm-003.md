# RM-003: Eval Report Artifact + Dashboard

## Goal

Build a queryable eval-report artifact and CI-linked dashboard that:
1. Persists per-run eval scores from the behavioral eval suite (RM-002) into a structured, queryable format
2. Reports coverage gaps: skills with zero eval records and deferred/excluded-by-default evals
3. Captures and links the first passing steady-state green run of the weekly Behavioral Eval on `main` (earliest candidate: scheduled 2026-09-21) as the green counterpart to RM-002's negative-path canary (run 35108912831), or documents why none can be produced
4. Adds **three-layer eval gating** so regression detection shifts left from weekly-only to pre-commit → advisory pre-push → enforced per-change PR check:
   - **Layer 1 (pre-commit)**: Hermetic validators only (`validate_skill.py` + fixture `verify.mjs`) wired via a git hook installer (`scripts/install-hooks.sh` creating `.git/hooks/pre-commit`). Runs in ~14s, catches malformed skills/fixtures before any commit. Zero CI minutes.
   - **Layer 2 (advisory pre-push)**: OPTIONAL single-skill behavioral eval for the changed skill only, explicitly labeled **"courtesy-feedback-not-evidence"**. Quarantine state stays CI-owned (local runs never write `quarantine.json`). Advisory only — never blocks.
   - **Layer 3 (enforcement, per-change PR check)**: `eval-per-change.yml` as a required PR check — the un-bypassable gate (git hooks are bypassable via `--no-verify`; required checks are not). A **skill change** runs exactly that skill's single `"default": true` canary (primary-logic-path selection; fallback = first eval in file order when unmarked, surfaced as `no_default_marker`). A **harness change** (repo-root `scripts/`, `.github/workflows/`) runs the **six core skills' default evals** (each marked `"core": true`) — the pass-3 relevance list and alphabetical fallback are **deleted**. Selected evals run as a **one-eval-per-job matrix** (`fail-fast: true`, `max-parallel` configurable, start 3); an aggregation/report job `needs:[evals]` with `if: always()` so artifacts + SLA reporting survive a red eval. **Rationale**: per-change is a fast high-signal tripwire, not a shallow copy of the weekly gate; non-default evals only ever ran weekly, so their regression window is unchanged from the RM-002 status quo.
5. Bounds every opencode invocation with a **per-eval stall catcher** (`BEVAL_TIMEOUT_SECONDS`, default 240s) and records every retried transient as its **own run-log record** (`outcome=error`, `eval_pass=null`, `detail='transient attempt N: <output>'`) — a silent hang is a bounded, logged, retried, quarantinable event, and a later success cannot bury the failure evidence.
6. Replaces the runner's blanket prose-substring assertion with a **closed, typed assertion protocol** — `action` (event predicates over the `opencode run --format json` session stream), `artifact` (a file the agent wrote + key phrases checked in its content), `text` (key-phrase in the response, narrowed to genuinely speech-shaped behaviors) — with the **nature rule** selecting the class (act → action; produces a file → artifact; literally speech → text). Enforced at Layer 1 (a NEW or CHANGED eval must be typed), telemetered as a dated `legacy_assertion` migration backlog in `coverage-gaps`, and applied this pass to the **seven core/default canaries** so each asserts agentic behavior the harness can actually observe. The pass-4 matrix run proved the shape but exposed the defect this fixes: the runner asserted `expected_behavior` as a verbatim response-text substring while evals were authored semantically, so a competent response essentially cannot pass.

- Historical trend visualization beyond what `query_runs.py aggregate` already provides
- Modifying the `run_behavioral_eval.py` assertion logic (only adding retry/quarantine wrappers and core-eval selection)
- Replacing the weekly scheduled eval (it remains the authoritative regression gate)
- Running **non-default** evals on the per-change path (a skill change runs only that skill's one default canary; the weekly full suite owns the rest)
- Marking/documenting a `"default": true` canary for **all** skills (pass 4 marks only `authoring-skills` and `observing-runs`; the five other core skills use first-eval fallback and every unmarked skill is surfaced via `no_default_marker` — rollout is a follow-up)
- Any harness-relevance list or alphabetical fallback (both deleted; a harness change always runs the fixed six-core set)
- Eval-model A/B during the 2026-09-19 free-tier gateway degradation — the degradation is shared-gateway, not model-specific, so no model comparison is answerable mid-window
- Additional live network probes beyond the recorded 2026-09-19 6-parallel concurrency probe
- Migrating all ~63 evals to typed assertions this pass — only the **seven core/default canaries** migrate; the rest stay legacy (flagged in `legacy_assertion_evals`) and migrate on touch (AC19)
- Removing or rewriting legacy `expected_behavior` this pass — coexistence is deliberate; typed `expect` wins at run time, legacy entries keep working
- Any typed predicate class beyond the closed three (`action`, `artifact`, `text`) — no `exit_code`, `database`, or `network` class is added
- Requiring a live model in tests — every matcher test replays a committed event-stream fixture or the hermetic stub path; the live behavioral authority stays the weekly/per-change run
- Redefining the RM-001 run-log schema — `legacy_assertion` is computed from manifests in `coverage-gaps`, not written as a run-log field

## Architecture

### Three-Layer Eval Gating Topology

| Layer | Trigger | Scope | Runtime | Enforcement | Purpose |
|-------|---------|-------|---------|-------------|---------|
| **1. Pre-commit** | `git commit` (via installed hook) | Hermetic validators only: `validate_skill.py` + fixture `verify.mjs` | ~14s | Advisory (bypassable via `--no-verify`) | Catch malformed skills/fixtures before commit; 0 CI minutes |
| **2. Advisory Pre-push** | `git push` (optional, opt-in) | Single-skill behavioral eval for changed skill only | ~30–60s | **Never blocks**; labeled "courtesy-feedback-not-evidence" | Fast local feedback; quarantine state CI-owned only |
| **3. Per-change PR Check** | `pull_request` / `push` to `main` (required check) | Skill change → that skill's one `default` canary via mapping table (first-match-wins); harness change (repo-root `scripts/`, `.github/workflows/`) → the **six core** skills' default evals | ≤12 min target; 20 min job ceiling; matrix fail-fast red in 2–3 min | **Required check — un-bypassable** | Enforcement gate; regression detection per-change (tripwire, not full-suite copy) |

**Rationale**: Git hooks are bypassable (`--no-verify`); required PR checks are not. Layer 1 catches syntax/structure errors instantly at zero CI cost. Layer 2 gives developers optional fast feedback without CI load. Layer 3 is the authoritative gate that cannot be skipped. **Pass 4 scope decision**: Layer 3 runs only each changed skill's one `default` canary; a harness change runs the fixed **six-core-default** set. Running the whole skill suite per change was never the design — the first live run (PR #23, run 35392700424) proved it cannot fit the budget, and non-default evals' regression window is unchanged from weekly-only RM-002. Selected evals run as a one-eval-per-job matrix (fail-fast) so a red eval surfaces in 2–3 min and the aggregation/report job still runs (`if: always()`).

### Data Flow

```
Layer 1: Pre-commit (local, zero CI)
    │
    ├─→ validate_skill.py (skill structure + frontmatter)
    │
    └─→ verify.mjs (fixture schema validation)
          │
          └─→ PASS → commit proceeds | FAIL → commit blocked (--no-verify to bypass)


Layer 2: Advisory Pre-push (local, opt-in, courtesy only)
    │
    ├─→ changed-files-to-skills.py <changed_files> → [skill]
    │
    ├─→ run_behavioral_eval.py --skill <skill> --model opencode/nemotron-3-ultra-free
    │       │
    │       ├─→ log_run.py (kind=eval records → local logs/)
    │       │
    │       └─→ (on transient failure) retry once
    │
    └─→ Output labeled "courtesy-feedback-not-evidence"
            │
            └─→ NEVER writes quarantine.json; NEVER blocks push


Layer 3: Per-change PR Check (CI, required, un-bypassable)
    │
    ├─→ changed-files-to-skills.py <changed_files> → class + [skill1, skill2, ...]
    │       │
    │       └─→ Mapping table: first-match-wins; three classes (see below)
    │
    ├─→ skill change:   resolve each changed skill's --default canary (fallback: first eval)
    ├─→ harness change: resolve the six core skills' --core default evals
    │       │
```

### Per-Change SLA / Latency Budget (pass 4 — marker-selected math)

**Basis: ~100s per fresh-agent behavioral eval, measured** on the first live
per-change run (PR #23, run 35392700424; 12 evals exceeded the old 20 min
ceiling). The prior 30s/eval figure was imaginary and is superseded. Stalls add
up to **2×240s worst case per eval** (one 240s stall + one bounded retry).

| Scenario | Max Skills | Max Evals | Est. Wall Time | Target | Timeout |
|----------|------------|-----------|----------------|--------|---------|
| Single skill change | 1 | 1 | ~2 min | ≤ 5 min | 20 min |
| Two skill changes | 2 | 2 | ~3–4 min | ≤ 12 min | 20 min |
| Harness change (repo-root scripts/, .github/workflows/) | 6 (core set) | ≤ 6 | ~10–11 min | ≤ 12 min | 20 min |
| Docs-only / non-evaluable change | 0 | 0 | ~0s | N/A | N/A (exits early) |

The `eval-per-change` workflow keeps `timeout-minutes: 20` as the static ceiling
for the whole matrix; each matrix job runs one eval. Because `fail-fast: true`,
a red eval cancels in-flight siblings and surfaces in **2–3 min**. The
per-scenario Timeout column is the budget the CI summary reports against. The
workflow selects the eval set deterministically via `--default` (skill changes)
or `--core` (harness changes); it does not compute `timeout-minutes`
dynamically. Docs-only changes exit immediately with "no behavioral surface
changed".

**Concurrency evidence (2026-09-19 probe)**: 6 parallel free-tier eval sessions
completed with **zero 429/rejections** — the matrix premise holds. `max-parallel`
starts at 3 and is raised only after a clean CI run.

### Flaky-Test Mitigation: Retry + Quarantine + Stall Catcher

- **Retry**: In `run_behavioral_eval.py`, wrap `invoke_opencode` in a 1-retry loop for `outcome in ("error", "failure")` where `detail` contains transient indicators (network timeout, model unavailable, rate limit, stall). Retry uses exponential backoff (2s, then 5s). Only one retry per eval per run.
- **Stall catcher (already landed, `9cbe3e8`)**: every opencode invocation is bounded by `BEVAL_TIMEOUT_SECONDS` (default 240s). On `subprocess.TimeoutExpired` the handler kills the **process group** and returns a synthetic `eval stall: ... timed out ... (transient; subprocess group killed)` failure that `is_transient()` classifies — 1 retry with backoff, then quarantine counting. A silent hang is never an outcome. Proof: `scripts/test_stall_timeout.py` (red-first, no zombies).
- **Per-attempt reliability annotation (already landed, `d3024ca`)**: every retried transient gets its **own run-log record** (`outcome=error`, `eval_pass=null`, `detail='transient attempt N: <output>'`) before the retry. Aggregators exclude `eval_pass=null` rows from the pass-rate denominator (RM-001 null semantics) while still counting them in runs/tokens — a later success cannot bury the failure evidence. Verified in `query_runs.py` (`eval_pass is None: continue` before `eval_rows += 1`).
- **Quarantine**: `quarantine.py` maintains `logs/quarantine.json`:
  ```json
  {
    "writing-unit-tests#3": {"fail_count": 3, "first_fail": "2026-09-15", "last_fail": "2026-09-18", "status": "quarantined"},
    "validating-ui#1": {"fail_count": 1, "first_fail": "2026-09-18", "last_fail": "2026-09-18", "status": "watching"}
  }
  ```
  - On 3rd consecutive failure → `status: "quarantined"`, excluded from default run (like `deferred: true`)
  - Quarantined evals appear in `coverage-gaps.json` under `quarantined_evals`
  - Manual clearance: `python3 scripts/quarantine.py clear <skill>#<eval_id>`
  - **Quarantine is CI-owned**: Layer 2 (advisory) runs never write `quarantine.json`.

### Green-Run Definition (AC10)

A **steady-state green run** is a weekly `eval-behavioral` workflow run on `main` where:
1. All **included** evals pass (`eval_pass=true` for every record)
2. Zero quarantined evals changed state during that run (no new quarantines, no releases)
3. The run completes within the **weekly** SLA budget (≤120 min; full ~63-eval suite ≈ 105 min at the measured ~100s/eval). The definition's basis stays the weekly full suite — only the budget number changed in pass 3 (was ≤20 min, which no run could meet)
4. The run is on `main` branch (not a fork or PR)

The first such run on or after 2026-09-21 becomes the "green counterpart" to RM-002's negative-path canary (run 35108912831). Its run ID and artifact link are recorded in `green-run-status.json` and displayed in the dashboard.

If no qualifying run exists by implementation time, `green-run-status.json` contains:
```json
{
  "achieved": false,
  "reason": "No steady-state green run observed as of 2026-09-18. Candidates: weekly runs on 2026-09-21, 2026-09-28. Blockers: <specific flaky evals or infra gaps if known>.",
  "candidate_runs": []
}
```

### Cost/Quota Guardrail (pass 4 — marker-selected counts)

- **Layer 1 (Pre-commit)**: 0 CI minutes (runs locally). Burns ~14s local developer time per commit.
- **Layer 2 (Advisory Pre-push)**: 0 CI minutes (runs locally, opt-in). Burns ~30–60s local developer time per push. **Trade-off**: saves Actions minutes but shifts latency to developer machine; advisory only.
- **Weekly run (full suite)**: ~63 evals × ~100s = ~105 min/run. × 4 runs/month ≈ **~420 min/month**.
- **Per-change run (Layer 3 PR)**: skill change = 1–2 `default` canaries ≈ **~2–4 min**; harness change = ≤6 `core` defaults ≈ **~10–11 min** (no `--limit` dependency).

  ```json

  ```
- The per-change workflow reads this at start; if `projected_monthly + estimated_this_run > 1800`, it fails fast with "Quota guardrail: projected monthly minutes would exceed 90% limit". Projection is still ~525 min/month (well under 1,800), so the guardrail is not expected to trip.
