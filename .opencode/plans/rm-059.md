# Plan: rm-059

## Goal / Approach

`scripts/watch_agent.py` must stop reporting `STALLED` for a subagent whose
session stream is demonstrably advancing, while still firing `STALLED` on
genuine silence (RM-059, Now, score 6).

Root cause (probed live 2026-10-24, read-only): the verdict's session-stream
age measures part **creation** only — `analyze_session` takes the newest
`part.time_created`. During a long generation opencode inserts no new part
rows but grows the current `reasoning`/`text` rows **in place**: the probe
showed a mid-generation `reasoning` part with `created_age=47s /
updated_age=2s` (the DB has a `time_updated` column `load_parts` ignores;
quiet sessions show equal ages, so the signal is real and discriminating).
The child's heartbeat also stalls mid-generation (it logs between calls), so
`min(hb_age, s_age)` crosses the stall window and a working child reads
STALLED. RM-022's no-tool-durations fact stands — the probe found tool parts
still written once at completion (`start≈end`); this fix does not touch that.

Approach: fix the stream-activity age at the source. `load_parts` also
selects `part.time_updated` and injects it into the parsed part dict as
`_time_updated` — **no tuple-arity change**, so the `(ms, d)` unpacking in
`has_terminal_result`, `session_guard._permission_denial`, and
`observe_completion` is untouched. `analyze_session` computes
`last_change_ms` (freshest of creation and in-place change, degrading to the
creation age when the key is absent). `verdict()` uses it as the stream age —
gating **both** `STALLED` and `DEAD` (one liveness variable; fixing only
STALLED would leave the false positive live at the DEAD tier). The STALLED
`why` line names its evidence basis (`no stream change for <age>`) per the
detail file's quiet-vs-delta convention.

## Open Questions

Each question leads with its heart (`reference/technical-english.md`
rule 19); the recommendation follows. Veto any default at approval.

1. **Which timestamp says "the child just wrote something"?**
   Recommended: the last-changed timestamp on each entry of the child's
   session log (`part.time_updated` in `opencode.db`). Every log entry
   carries two timestamps: when it appeared, and when its content last
   changed. While a child generates output, nothing new appears but
   existing entries keep changing — so "last changed" is the only clock
   that moves. The other clocks (the session's totals) move only later,
   so they add code without catching anything sooner.
2. **Fix the age once, or the false alarm survives under another name?**
   Recommended: fix once. STALLED and DEAD read the same age; correcting
   the age heals both. Correcting only STALLED leaves the false alarm
   escalating — DEAD authorizes the stronger intervention.
3. **No playbook exists for this kind of repo.**
   Recommended: proceed anyway. The design skill ships playbook templates
   for web-app stacks (Vue or Next.js + Supabase). This repo is different
   — a library of Python scripts and agent skills — so no template
   applies and the plan reasons from first principles. No decision needed
   from you.
