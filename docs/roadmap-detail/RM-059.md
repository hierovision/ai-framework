# RM-059 — Watchdog STALLED false positive on active generation

> Detail file for roadmap row `RM-059`. Status and rank live in `docs/ROADMAP.md`; this file is provenance.

Source: live observations 2026-10-12/13 (both the RM-056 design pass and the RM-056 implement pass printed `STALLED` while `stream.jsonl` timestamps advanced); the RM-022 record already notes opencode publishes no tool durations.

## Failure shape

`watch_agent.py` computes the stall verdict from inter-event quiet gaps in the session event stream. During long text generation opencode publishes no tools/spans, so a working child reads as silence, and the verdict prints STALLED though the stream shows `step_start` / `step_finish` events advancing. Observed twice live on 2026-10-12/13 (RM-056 design pass at ~12:10–12:35; RM-056 implement pass during its full-verification call).

## Why it matters

The verdict's reader (the orchestrator agent) treats STALLED as "the child is dead or wedged" and intervenes — killing or resuming a live run destroys paid progress and wastes the dispatch. RM-049 documents the sibling case (blocking-wait on completed children); RM-047 fixed completion-state predicates. This row carries the troisième sibling: generation-silence.

## Fix direction

Gate the STALLED emit on state deltas, not quiet gaps: the watchdog must require that NOTHING in the session stream changed across the observation window (no events of any kind, not merely no tool calls) before STALLED may report. Drill: fabricate advancing events at cadence while the window runs and assert the verdict stays non-STALLED; fabricate true silence over the same window and assert STALLED still fires. Sibling drill exists for RM-049.

## Interim handling (in effect until the fix lands)

While a child works, status reports label stall alerts by their *evidence
basis* (quiet-vs-delta) instead of the raw verdict wording; the orchestrator
verifies stream advancement before treating STALLED as an intervention
instruction.
