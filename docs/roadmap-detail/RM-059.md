# RM-059 — Watchdog STALLED false positive on active generation

> Detail file for roadmap row `RM-059`. Status and rank live in `docs/ROADMAP.md`; this file is provenance.

Source: live observations 2026-10-12/13 (both the RM-056 design pass and the RM-056 implement pass printed `STALLED` while `stream.jsonl` timestamps advanced); the RM-022 record already notes opencode publishes no tool durations.

## Failure shape

`watch_agent.py` computed the stall verdict from part **creation** timestamps in the session event stream. During long text generation opencode inserts no new parts, so a working child reads as silence and the verdict prints STALLED though the stream is advancing. Observed twice live on 2026-10-12/13 (RM-056 design pass at ~12:10–12:35; RM-056 implement pass during its full-verification call).

## Why it matters

The verdict's reader (the orchestrator agent) treats STALLED as "the child is dead or wedged" and intervenes — killing or resuming a live run destroys paid progress and wastes the dispatch. RM-049 documents the sibling case (blocking-wait on completed children); RM-047 fixed completion-state predicates. This row carried the third sibling: generation-silence.

## Delivered (2026-10-25)

Landed on `feat/rm-059` (PR pending at the rule-6 closure commit):

- **The signal.** `load_parts` now also selects `part.time_updated` and injects
  it into the parsed part dict as `_time_updated` — the tuple stays
  `(time_created_ms, data_dict)`, so every `(ms, d)` unpacking
  (`has_terminal_result`, `session_guard._permission_denial`,
  `observe_completion`) is untouched. A store without the column (older
  schema) falls back to creation-only ages instead of failing the pass.
- **The clock.** `analyze_session` computes `last_change_ms`: the freshest of
  creation and in-place change across the parts. `verdict` reads it through
  one `_stream_age` helper (with a defensive fallback to `last_ms` for an
  analysis dict that predates the field). `_report`'s last-event line and
  `--json`'s `session_age_s` use the same helper.
- **Both tiers gated.** STALLED and DEAD read the one liveness age; fixing
  only STALLED would have left the false alarm escalating at the DEAD tier,
  which authorizes the stronger intervention.
- **Evidence basis in the alert.** A STALLED `why` line now reads
  `no stream change for <age>` instead of `quiet for <age>`, matching the
  quiet-vs-delta convention the detail file had recorded as interim handling.
- **Reference facts.** `reference/opencode-integration.md` documents the
  in-place generation delta (dated probe 2026-10-24: mid-generation
  `reasoning` part `created_age=47s / updated_age=2s`; quiet sessions show
  equal ages); `reference/subagent-supervision.md` §4 describes the liveness
  clock as the freshest of heartbeat and stream change.

### Design decisions carried

1. **In-place `time_updated` is the delta signal.** No new part rows appear
   mid-generation; the current `reasoning`/`text` row grows in place, so its
   `time_updated` is the only clock that moves. Probed read-only on the live
   DB before design.
2. **Parts-only clock.** Session totals (`session.time_updated`, token
   counters) move only later, so they add code without catching anything
   sooner; the part stream is the earliest honest movement.
3. **DEAD included.** One liveness variable for both tiers — see above.
4. **Heartbeat-only mode is a stated residual.** With no DB there is no
   advancement evidence to gate on; the mode is unchanged by design, not by
   oversight.

## Evidence

- **Red-first, both directions.** `test_streaming_generation_not_stalled`
  failed on the missing injected `_time_updated` and the guard case failed
  with `['stalled']` before the edit. True silence (300 s → STALLED, 600 s →
  DEAD) passed on the pre-fix code, proving the net direction was not
  weakened; it stays green after the fix with the new basis line.
- **Verification.** `test_watch_agent.py` 18/18, `test_session_guard.py`
  27/27, `test_observe_completion.py` 10/10, `test_dispatch_agent.py` 24/24 —
  all exit 0; `py_compile` clean on the touched scripts.
- **Runtime CLI drill.** A fixture DB with creation 300 s old and in-place
  change 5 s old returns `OK` (exit 0, `session_age_s` 5.0); mutating the
  change to stale returns `STALLED` (exit 2, `no stream change for 5.0m`).
- **Live silence observation.** A 45 s observer of the live implementer
  session saw the new basis fire on genuine pause: 16 s → STALLED, 31 s →
  DEAD. A live *mid-generation* drill against a real long-running child
  remains the manual handoff item — self-observation is confounded because
  the outer turn's tool part stays `running` (BLOCKING) for its duration.

## Residual / follow-up

`session_guard._recent_event` (result-level recency) still reads creation
age. A mid-generation child with a **reasoning-only** stream (no text part
yet) can therefore still draw an `empty-result` flag even though the
liveness gate no longer stalls it. `scripts/session_guard.py` was outside
this plan's Files to Modify; candidate follow-up row.

The plan artifact (`.opencode/plans/rm-059.md`) was retired per AGENTS.md
rule 4 — its essence is this section plus the shipped code and the two
reference facts above.
