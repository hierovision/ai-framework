# RM-059 — Watchdog STALLED false positive on active generation

> Detail file for roadmap row `RM-059`. Status and rank live in `docs/ROADMAP.md`; this file is provenance.

Source: live observations 2026-10-12/13 (both the RM-056 design pass and the RM-056 implement pass printed `STALLED` while `stream.jsonl` timestamps advanced); the RM-022 record already notes opencode publishes no tool durations.

## Failure shape

`watch_agent.py` computed the stall verdict from part **creation** timestamps in the session event stream. During long text generation opencode publishes nothing on that surface, so a working child reads as silence and the verdict prints STALLED. Observed twice live on 2026-10-12/13 (RM-056 design pass at ~12:10–12:35; RM-056 implement pass during its full-verification call).

## Why it matters

The verdict's reader (the orchestrator agent) treats STALLED as "the child is dead or wedged" and intervenes — killing or resuming a live run destroys paid progress and wastes the dispatch. RM-049 documents the sibling case (blocking-wait on completed children); RM-047 fixed completion-state predicates. This row carried the third sibling: generation-silence.

## Falsification trail (2026-10-25, the reason for v2)

The first fix gated liveness on `part.time_updated`, on a 2026-10-24
reading of a mid-generation `reasoning` part at `created_age=47s /
updated_age=2s`. Three live drill dispatches (read-only `planner` children,
per-second polling, full visibility flags) falsified that premise:

- **No timestamp in `opencode.db` moves during token streaming.** 8/8 DB
  deltas were new row insertions; mid-generation the newest `reasoning`
  part stayed frozen for up to ~129 s. The 47s/2s sighting was a block
  completion, not a streaming delta.
- **The dispatcher's `--stream-out` tee is block-granular.** A 2111-word
  generation arrived as three events (`step-start`, `text`, `step-finish`).
- **So no DB/tee delta gate can close a >240 s single-step generation.**
  The shipped change remains as the DB lane's clock and defensive
  coverage, but it does not close the incident shape alone.

## Delivered (2026-10-25, v2 — two lanes)

Landed on `feat/rm-059`:

- **Lane A — vendor status, preferred.** `--server-url` (env fallback
  `OPENCODE_WAKE_URL`) resolves a known-port server; `session_status(url,
  sid)` reads `GET /session/status` defensively (absent URL/server/entry →
  `None`, never a crash). `busy` is demonstrably generating → `OK`, named in
  the `why`; `retry` is surfaced with its attempt/message and never reads
  OK (exit code stays 2); absent/`idle` falls through to Lane B.
- **Lane B — DB fallback with open-step grace.** When the stream's newest
  part is inside an **open assistant step** (trailing `step-start`, no
  `step-finish` after), silence stretches to `--generation-seconds`
  (default 600) before STALLED may fire; past 2× the grace fires DEAD.
  Quiet **not** inside an open step keeps the plain 240 s window. The
  open-step predicate is `watch_agent.assistant_step_closed` with the same
  semantics as `observe_completion._assistant_step_closed` (parity-tested;
  the observer file is untouched per the RM-058 seam).
- **The retained DB handling.** `load_parts` still selects
  `part.time_updated` and injects `_time_updated` (tuple arity unchanged;
  older stores degrade to creation-only); `analyze_session` computes
  `last_change_ms`; `verdict` gates both STALLED and DEAD on the one
  windowed age, and the STALLED `why` names `no stream change for <age>`.
  `_report`/`--json` share the age.
- **References.** `reference/opencode-integration.md` replaced the
  falsified in-place fact with the measured block-granular truth and the
  server-surface facts; `reference/subagent-supervision.md` §4 carries the
  lane order and the event-type discipline (never map `session.updated`).

### Design decisions carried

1. **The vendor's status is the authoritative liveness signal when it is
   visible.** A durable write clock cannot see an in-flight model call;
   the server knows.
2. **The status map is per owning server.** Measured: a run-vehicle child
   on its own embedded server generated ~130 s while a separate `serve
   --port 4096` (same DB) reported `{}`. Lane A covers children owned by
   the polled server; Lane B carries the rest. Attaching dispatches to the
   known-port server is a separate design change (Open Question in the
   retired plan), not widened into this row.
3. **Open-step grace is the honest DB fallback.** Mid-block the vendor
   publishes nothing, so the budget is the dispatch checkpoint bound
   (600 s), not the inter-block window.
4. **DEAD reads the same window.** Fixing only STALLED would leave the
   false alarm escalating at the tier that authorizes the stronger
   intervention.
5. **One step predicate.** Parity-tested against the observer's helper
   rather than redefined silently.
6. **Retry surfaces without a new verdict word.** `retry` → STALLED with
   the retry state named; exit 2.

## Vendor probe (2026-10-25, opencode 1.19.4)

- `GET /global/health` → `{"healthy":true,"version":"1.19.4"}`.
- `GET /session/status` → `{"<sessionID>": {"type": "busy"|"retry"|...}}`;
  entries carry **only `type`** — no `parentID`, no timing fields.
- Cross-instance: `{}` throughout a run-vehicle child's ~130 s generation
  (per-instance map, consistent with #35472).
- Owning server: `busy` → entry absent ~1 s after process exit; no
  explicit `idle` entry observed.
- `GET /event` is an SSE stream (`content-type: text/event-stream`;
  first frame `server.connected`).
- Recorded in `reference/opencode-integration.md` (volatile, re-verify on
  touch).

  `KeyError: step_open`; AC10 failed with `TypeError: status=`; parity

  24/24 — exit 0; `py_compile` clean.
- **Live success-measure drill (run-vehicle, cross-instance):** a
  `planner` child generated 3.7 min / 5851 words in one step; 20/20
  `--watch` polls returned `OK`, Lane A correctly absent, Lane B carried
  it, no server error. Max DB quiet in that run was 101 s (the step
  splits into reasoning/text blocks), so the >240 s boundary itself is
  proven by the AC9 drill, not this run.
- **Lane A live drill (attached child):** 12/12 `OK` polls; 10 named
  `server status: busy (generating)` while the DB clock reached 43.9 s
  against a deliberately small 30 s window — decisive proof that `busy`
  overrides the DB tier.

  design — documented residual.
