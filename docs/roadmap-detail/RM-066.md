# RM-066 — Roadmap contract coherence — ordering + five more spec conflicts

> Detail file for roadmap row `RM-066`. Status and rank live in `docs/ROADMAP.md`; this file is provenance.

Source: hierovision/ai-framework#113; consumer conformance scan 2026-10-12/13 against `Stonegate-Software/paragon-learning-network`.

## Observed

The owner-approved presentation/lifecycle increments of 2026-10-11/12 (RM-056/057 — per-horizon glance strips, per-ID detail dirs, 13-column Done) landed in the framework's own `docs/ROADMAP.md` (commit `4d0d035`) but the shipped skill, format, and checker were not fully brought along. Consumers following the contract produce non-conforming roadmaps. Six coherence problems:

1. **Ordering contradictory/underspecified.** `roadmap-format.md` says "ranked list … highest first. Mirrors the tables below" (flat, no rule for table order); `SKILL.md` says horizon-grouped `Now`/`Next`/`Later`, ordered by `Score` then `ID`, with scope and direction unstated — it conflicts with "highest first". Framework practice is one list per horizon, rank order. No eval pins ordering.
2. **`proposed` → `open` transition undefined.** Format and skill only say new items append as `proposed`; nothing says when a proposed item becomes `open`. The consumer has 9 scored rows still `proposed`, one ranked in the top ten, alongside triage-flipped `open` rows.
3. **`review` category means two different things.** Triage docs: a transitional escape hatch ("awaiting user decision"; "not permanently parked"). Practice (vision-session slices; the consumer's Review table): a durable track for owner-led research/discovery running for weeks.
4. **Done-adoption amendment has no consumer migration path.** The 2026-10-11 amendment (historical prose moved verbatim to `docs/roadmap-detail/<ID>.md`) migrated the framework's own roadmap but says nothing for pre-amendment consumer roadmaps; the scanned consumer's ADR explicitly chose "old-schema rows are not rewritten" — now in direct conflict.
5. **`check_roadmap_verbatim.py` unusable for consumers.** Not distributed (`install.sh` links `skills/`, `agents/`, `reference/` only); hard-codes `docs/ROADMAP.md` while the skill says `ROADMAP.md` at repo root; hard-fails a per-ID detail-file bijection for all rows while the format presents detail files as conditional.
6. **Section layout diverges from framework practice.** Contract §Section order mandates category sections (Features / Bugs / Tech Debt / Chores); the framework's own roadmap uses horizon sections with 13-column tables and no category sections. Canonical layout for consumers is unstated.

## Expected

One coherent contract: a single ordering rule (horizon-grouped, score-desc, then ID) applied to both the glance list and the tables and pinned by an eval; a defined `proposed` → `open` transition; one meaning for `review` with `facilitating-product-vision` emitting consistently; a stated consumer migration path for the Done-adoption amendment; a distributable `check_roadmap_verbatim.py` whose location and bijection semantics match the format text; and a canonical section layout.
