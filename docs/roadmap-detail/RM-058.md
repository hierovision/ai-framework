# RM-058 — Orchestrator wake-on-completion — concurrent subagent interaction + owner-free notifications

> Detail file for roadmap row `RM-058`. Status and rank live in `docs/ROADMAP.md`; this file is provenance.

Source: user directive 2026-10-12; supervision stack RM-022/RM-045/RM-032; AGENTS.md rule 1 boundary.

## Requirements (owner statement, 2026-10-12)

1. The owner can interact with the orchestrator while a background subagent task runs (concurrent conversation + dispatch). Today this works because the child runs detached (setsid) and the orchestrator's turns are free.
2. When the subagent reaches a terminal state (success / failure / abort), the orchestrator is informed and reports to the owner WITHOUT the owner pinging. Today this does NOT exist: the orchestrator only runs when the user sends a message; the completed-child state is durable on disk (heartbeat, stream, result, run log) but nothing wakes it.

## In-scope design territory (the discovery this pass must own)

- The completion-observer (watchdog loop vs opencode event hooks) — decide on evidence from the installed opencode.
- The wake path into the orchestrator conversation; how it respects AGENTS.md rule 1 (no parent-session store corruption from sibling processes)
- The standard dispatch contract gains an explicit wake contract: no repeats of today's failure (declaring a dispatch "running" before it runs; orchestrator claims gated on a real poll).
- **Worktree-safe dispatch** — discovered live on 2026-10-13: children that touch branches must run in their own git worktree so the parent/agent working tree always stays on main (removes an entire failure class: child commits on the wrong parent branch, parent commits landing on child branches).

## Out of scope

- Push-channel to any external service (email/phone); the orchestrator conversation is the only sink.
- Any routing-policy coupling.

## Chronic instance (2026-10-14): per-dispatch permission profile

Three dispatches this week died mid-recon on `permission denied: external_directory`
denials outside the working tree: `~/repos/temp/*` (RM-056 design, 2026-10-11),
`~/.config/opencode/*` (RM-056 fix, first attempt 2026-10-14), and
`~/.local/share/opencode/*` (RM-056 fix, second attempt 2026-10-14). Each was
recoverable only by a manual `--allow-dirs` retry. Design requirement: the
dispatch contract should carry a least-privilege default profile per agent class
(implementer/architect) so recon reads never die on the first turn — the
wake-on-completion design pass should fold this into the same contract.

## Delivered (2026-10-16)

Shipped in [PR #116](https://github.com/hierovision/ai-framework/pull/116):

- **Worktree-safe dispatch (D3).** `--worktree <name>` runs a branch-touching child in its own `git worktree` (`dispatch/<name>`), so the parent tree never leaves `main`; the interim no-parent-git rule is retired.
- **Per-dispatch permission profile (D4).** `scripts/dispatch-profiles.json` — least-privilege read roots per agent class, union-merged with explicit `--allow-dirs`.
- **Completion-observer + attach-vehicle wake (D1/D2).** `scripts/observe_completion.py` polls the durable surface (heartbeat + run log) and delivers the wake through the orchestrator's own server: `opencode run --attach <url> --session <id> --agent <agent>`. Launch workflow: `OPENCODE_WAKE_URL=http://127.0.0.1:<port> opencode --port <port>`.
- **Status-claim gate (D5).** Heartbeat line ownership (`SURVEY` / `WAKE` / `WAKE_DEFERRED reason=`) plus the rule that a state is claimed only from polled durable lines.
- **Corrected quiescence gate.** No tool in flight AND no unclosed assistant step (a trailing `step-start` = a model call mid-generation) AND a stable `time_updated` across two polls.

### The 2026-10-15 ghost-turn defect and its fix

The first live smoke failed: `opencode run --session <id>` starts its **own** server and ran the wake as an out-of-band `agent=build` turn (`run=e59d1f4c`) while the live TUI held `run=be145e63` / `agent=curator` — so the wake persisted but never rendered. The plan's `opencode attach` remedy was infeasible (the TUI exposed no HTTP server). The amendment delivers through the TUI's own server instead: the owner launches on a fixed `--port`, and the wake attaches to it, forcing `--agent <wake-agent>`.

### AC8 live smoke (passed 2026-10-16)

A real detached recon child (`--wake-to <fixed-port-TUI-session> --wake-agent curator --wake-url http://127.0.0.1:4571`) finished at 12:27:10; the observer delivered and wrote `WAKE success` at 12:28:20 (~42 s, SLA 5 min); the wake **rendered** in the TUI (pty capture) and the stored turn ran as `agent=curator` (not `build`). Evidence: `.scratch/rm-058-ac8-smoke/`.
