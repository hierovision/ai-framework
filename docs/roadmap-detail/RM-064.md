## Detail at extraction

Checkpoint semantics proper — the half of the original RM-062 that RM-062's proactive restart-recovery does not cover. RM-062 makes the observation side restart-aware (reconcile orphaned dispatches); this row makes a **multi-phase run** resumable as a sequence.

Deliverable: persist a small phase state machine (phase list, current phase, one checkpoint per phase) so a resumed session continues from the last checkpoint instead of re-planning the whole run. Still files, still zero external services (plan §8) — no durable-execution engine.

**Gate** (owner decision 2026-10-16): RM-055's design pass — the chief-of-staff operating cadence is what makes multi-phase unattended runs real; designing checkpoints before that is speculating about a cadence that does not yet exist. Blocked-by RM-055.

Reference design if the file-based approach proves insufficient: Microsoft Agent Framework checkpointing/time-travel + Durable Task extension (fetched 2026-10-16) — explicitly not adopted now.

Design territory to own: the state-file schema, checkpoint boundaries (phase completion signals from the plan artifact), resume protocol and its interaction with the RM-058 wake surface, and failure semantics (partial phase, re-entry).
