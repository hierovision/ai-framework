# RM-072 — Delegation observer milestone noise

> Detail file for roadmap row `RM-072`. Status and rank live in
> `docs/ROADMAP.md`; this file is provenance.

Source: owner report 2026-11-06, during a session that ran two subagents
(marvin pre-commit scan, phasetimer Phase 0 review). The session surfaced 15+
`delegation-observer milestone` lines, each with no state or value; the owner
called it noise with no value in this interface.

## Observed

- Routine milestones (`start`, `first-tool`, `resume`) and the terminal event
  appear as standalone strip lines.
- The lines repeat; a delegate's state is not coalesced into one row.
- The surface is meant to be a live status strip (RM-069), not an append-only
  event log.

## Context

- RM-069 delivered the event-driven observer, status strip, milestones, and
  controls.
- RM-070 added bounded attention milestones (`thrash`, `stall`, `needs-input`,
  `denied`) that start one parent turn; routine and terminal milestones stay
  context-only.
- This row is a presentation/coalescing defect, not a new delegation semantic:
  attention and terminal behavior must not change.

## Pointers

- `plugins/delegation-observer/server.ts` — synthetic milestone emission.
- `plugins/delegation-observer/state.ts` — dedupe/rate/association.
- `plugins/delegation-observer/tui.tsx` — strip rendering/toasts.
- `reference/subagent-supervision.md` §7 — the observer contract.
- Tests: `server.test.ts`, `tui.test.ts`, `mutation-check.mjs`.

## Scope boundary

Included: coalesce routine milestones into one strip row per delegate, keep
attention and terminal milestones visible, and preserve the no-model-turn
rule. Excluded: changing wake/attention semantics, adding new milestone
kinds, a broader TUI redesign, or changing the observer's trust boundary.

## Verification idea

A multi-delegate test (and a live two-subagent session) shows at most one
strip line per delegate per meaningful state change, with attention and
terminal events still visible and no extra parent turns.
