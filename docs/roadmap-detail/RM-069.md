# RM-069 — Observable delegation — event-driven subagent status, milestones, controls

> Detail file for roadmap row `RM-069`. Status and rank live in

## Requirements (owner statement, 2026-10-29)

1. A start returns a handle; the owner keeps an interactive turn while the
   child runs (no foreground black box).
2. The child appears in a live status surface immediately, with decision-grade
   fields (agent, task, elapsed/quiet, tool/phase, tokens/cost, state).
3. Progress, needs-input and terminal state arrive from server events — the
   interactive view never reads heartbeat files.
4. Milestones are automatic, useful and bounded; they must not buy model
   turns.
5. The owner can focus/open, steer and interrupt from the surface, on the same
   session id.
6. Degradation is visible; the durable watchdog/wake remains the fallback.
7. No framework guidance may prescribe foreground/blocking delegation.

## Delivered

- **Plugin package** `plugins/delegation-observer/` — `state.ts` (pure reducer,
  association, rate/dedupe, thresholds, shared health record), `view.ts` (pure
  projections, association gap, controls, status snapshot), `server.ts`
  (event subscription, trust check, synthetic milestones, health record),
  `tui.tsx` (slots, toasts, attention, bindings, panel, degradation banner),
  `state.test.ts` / `tui.test.ts` / `server.test.ts`, `README.md`,
  `package.json`, `tsconfig.json`.
- **Universal association** — in-session `parentID`; run-vehicle
  `[delegate:<orchestrator-session-id>] <agent>: <task>` title marker emitted
  by `scripts/opencode_v2.py` and set by `dispatch_agent.py --delegation-to`
  (default `--wake-to`). Only an explicitly orchestrated dispatch joins the
  shared service; headless dispatch is unchanged.
- **Background handle** — `dispatch_agent.py --detach` returns immediately
  with pid/log/heartbeat/session-file, and the detached child keeps writing
  the heartbeat, streams, result, run log and `<heartbeat>.session`. This is
  the orchestrator's non-blocking run-vehicle path.
- **One supervision vocabulary** — `scripts/supervision_contract.json`
  generated from `watch_agent.py` / `observe_completion.py`; the plugin's
  defaults are asserted equal (TS + Python).
- **Trust boundary** — before the first synthetic message, the parent must
  resolve as a root session (`session.get`); an unverified parent receives no
  injected message and the drop is visible in the health record. Marker
  fields are sanitized and round-trip-tested.
- **Controls** — focus via `ui.tabs.focus`, steer via
  `session.prompt({delivery:"steer"})`, interrupt via `session.interrupt`;
  `session_guard.py --interrupt` exposes the same typed call, with kill
  authority unchanged. Bound to `alt+d` / `alt+s` / `alt+x` / `alt+p` /
  `alt+h` (palette/slash entries are also declared, but this 2.1.4 TUI does
  not surface plugin commands there — see the drill note).
- **Degradation** — banner + footer marker for absent/failed plugin,
  disconnected stream, disabled config, unassociated running *child*
  sessions (the root is excluded), and the server's shared health record
  (`<location>/.scratch/delegation-observer/health.json`). The observer's
  opt-in `--status-file` snapshot is read by the `delegation.status` command.
- **Guidance sweep** — `reference/subagent-supervision.md` §7,
  `reference/agent-teams.md` (background handles, `--detach`, delivery),
  `reference/opencode-integration.md` (dated V2 event/TUI/synthetic facts),
  and the four skills that previously said "invoke the subagent" now name the
  handle and the delivery contract. `check_v2_surfaces.py` fails on new
  foreground/blocking/fire-and-forget wording.

## Review round 3 fixes

- **Config end-to-end for the TUI.** `tuiConfig` maps
  `DELEGATION_OBSERVER_ENABLED/STALL_SECONDS/HEALTH_FILE/STATUS_FILE` (options
  still win when forwarded); a custom health path and a disabled observer now
  affect the TUI (tests + D6 disabled drill).
- **Nested routing.** The server walks the parent chain to the root and
  follows a run-vehicle title marker; a depth-2 child's milestone reaches the
  real orchestrator (test + nested drill), with no false "unverified" banner.
- **Sentinel companion.** `plugins/delegation-sentinel/` (no-op server +
  TUI) renders the fallback banner when the observer is absent, failed,
  disabled, disconnected, or its TUI is not running; it reads the observer's
  presence marker (`tui.json`) and health record and never renders delegate
  detail. Tests + D6a/b/c.
- **Tool label.** `session.tool.called` has no name on 2.1.4: the call is
  labelled/counted when `session.message.content.updated` supplies the name
  (test); the content-update path is the live one.
- **Dead row recovery.** `touch` returns `failed` → `running` on real activity
  (test).
- **Health write throttle.** The health record is written on state change
  only (test counts two writes: init + stream end); presence marker every 10 s.
- **Trust residual.** Root-only trust is the accepted local boundary (any
  existing root named by a title passes); recorded in ADR-0015 as a residual,
  not a provenance proof.

## Known limits (tracked, not waived)

- A `thrash` warning is cleared by the next activity (`touch`); the durable
  dedupe signal is the single milestone, not a persisting red row. The strip
  shows the warning only between the third identical call and the next event.
- Trust is root-only: a title marker naming any existing root passes. This is
  the accepted local-context boundary, not a provenance proof.
- Headless/standalone children stay outside the live strip by design (the
  watchdog + terminal wake are their contract).
- This 2.1.4 build does not surface plugin palette/slash entries, so the
  controls are bound (`alt+d/s/x/p/h`).
- The TUI gets its config from the documented env source; a host that forwards
  plugin options wins per key (options > env > shared defaults).
