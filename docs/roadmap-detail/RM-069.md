# RM-069 — Observable delegation — event-driven subagent status, milestones, controls

> Detail file for roadmap row `RM-069`. Status and rank live in
> `docs/ROADMAP.md`; this file is provenance.

Source: owner directive 2026-10-29 — every delegated subagent, short or long,
must be non-blocking and observable without manual polling. This finishes the
half RM-058 deliberately deferred; it does not reopen RM-058's delivered
contracts. Decision: `docs/ADRs/ADR-0015-observable-delegation.md`.

**Status: in-progress** (re-opened after independent review of PR #134,
2026-10-29). Code and hermetic gates are complete; AC13's two-vehicle and
live loop/stall drills are not executable in this environment. A dated plan
amendment is requested below.

## Requirements (owner statement, 2026-10-29)

1. A start returns a handle; the owner keeps an interactive turn while the
   child runs (no foreground black box).
2. The child appears in a live status surface immediately, with decision-grade
   fields (agent, task, elapsed/quiet, tool/phase, tokens/cost, state).
3. Progress, needs-input and terminal state arrive from server events — the
   interactive view never reads heartbeat files.
4. Milestones are automatic, useful and bounded; they must not buy model
   turns.
5. The owner can focus/open, steer and interrupt from the surface, on the same
   session id.
6. Degradation is visible; the durable watchdog/wake remains the fallback.
7. No framework guidance may prescribe foreground/blocking delegation.

## Delivered

- **Plugin package** `plugins/delegation-observer/` — `state.ts` (pure reducer,
  association, rate/dedupe, thresholds, shared health record), `view.ts` (pure
  projections, association gap, controls, status snapshot), `server.ts`
  (event subscription, trust check, synthetic milestones, health record),
  `tui.tsx` (slots, toasts, attention, bindings, panel, degradation banner),
  `state.test.ts` / `tui.test.ts` / `server.test.ts`, `README.md`,
  `package.json`, `tsconfig.json`.
- **Universal association** — in-session `parentID`; run-vehicle
  `[delegate:<orchestrator-session-id>] <agent>: <task>` title marker emitted
  by `scripts/opencode_v2.py` and set by `dispatch_agent.py --delegation-to`
  (default `--wake-to`). Only an explicitly orchestrated dispatch joins the
  shared service; headless dispatch is unchanged.
- **Background handle** — `dispatch_agent.py --detach` returns immediately
  with pid/log/heartbeat/session-file, and the detached child keeps writing
  the heartbeat, streams, result, run log and `<heartbeat>.session`. This is
  the orchestrator's non-blocking run-vehicle path.
- **One supervision vocabulary** — `scripts/supervision_contract.json`
  generated from `watch_agent.py` / `observe_completion.py`; the plugin's
  defaults are asserted equal (TS + Python).
- **Trust boundary** — before the first synthetic message, the parent must
  resolve as a root session (`session.get`); an unverified parent receives no
  injected message and the drop is visible in the health record. Marker
  fields are sanitized and round-trip-tested.
- **Controls** — focus via `ui.tabs.focus`, steer via
  `session.prompt({delivery:"steer"})`, interrupt via `session.interrupt`;
  `session_guard.py --interrupt` exposes the same typed call, with kill
  authority unchanged. Bound to `alt+d` / `alt+s` / `alt+x` / `alt+p` /
  `alt+h` (palette/slash entries are also declared, but this 2.1.4 TUI does
  not surface plugin commands there — see the drill note).
- **Degradation** — banner + footer marker for absent/failed plugin,
  disconnected stream, disabled config, unassociated running *child*
  sessions (the root is excluded), and the server's shared health record
  (`<location>/.scratch/delegation-observer/health.json`). The observer's
  opt-in `--status-file` snapshot is read by the `delegation.status` command.
- **Guidance sweep** — `reference/subagent-supervision.md` §7,
  `reference/agent-teams.md` (background handles, `--detach`, delivery),
  `reference/opencode-integration.md` (dated V2 event/TUI/synthetic facts),
  and the four skills that previously said "invoke the subagent" now name the
  handle and the delivery contract. `check_v2_surfaces.py` fails on new
  foreground/blocking/fire-and-forget wording.

## Live evidence (isolated XDG config + isolated OPENCODE_DB; raw 2.1.4 binary)

Captures under `.scratch/rm-069/drills/` (gitignored):

- **D1 — in-session child, live.** TUI + free model in tmux. Parent dispatched
  one `explore` child; the strip rendered
  `· explore running: tool: sleep 120 ·` and later
  `· explore completed: completed · 28s`; two synthetic
  `delegation-observer milestone` entries appeared in the parent conversation;
  the parent turn completed (`DONE`) without waiting for a poll. DB evidence:
  child row with `parent_id` and 2 synthetic messages in the root.
- **D3 — controls, live.** `alt+d` focused the child tab; `alt+s` opened the
  steer dialog and the text was queued as a `session_inbox` user message with
  `delivery:"steer"` on the **same** child session id; `alt+x` interrupted it
  (`idle_outcome=interrupted`, parent reported the cancellation).
- **D5 — needs-input, live.** A child read outside the worktree; the strip
  showed `! explore waiting: permission: …` and a `needs-input` synthetic
  milestone naming the action; the toast path fired.
- **D4-busy — live.** With the drill threshold `stallSeconds: 5`, a running
  child's 25 s tool call stayed `running` at t+8 s and t+16 s (no false
  stall; the call budget applies).
- **Loader / degradation probes.** The real loader logs
  `loading plugin …/delegation-observer entrypoint=…/server.ts` and the
  plugin's `initialized` marker with isolated config/DB; a deliberately broken
  `server.ts` yields `failed to load plugin … ref=…` while the run continues.
  In the TUI, an earlier build's real load failure surfaced as
  `Plugin failed: …` / `TUI plugin error: … ctx.ui.keymap.layer` — the exact
  error that proved `ctx.keymap` (not `ctx.ui.keymap`) and was fixed.

**Not executed (AC13 residual):** D2 (run-vehicle child in the live TUI
strip) and a live loop/stall induction. Probes: `opencode --port` is
unrecognized in 2.1.4, so the standalone TUI exposes no server URL; an
isolated managed service starts (`service set port 4098`) but `/api/plugin`
is location-scoped and returned an empty list, and the TUI then correctly
showed `! delegates unavailable`; the only known-port shared service is the
live one, which owns the real session DB (off-limits). A live tool loop also
needs a model that repeats a call, which the free model would not do on
demand. The hermetic fixtures cover both paths
(`state.test.ts` thrash/stall/busy, `server.test.ts` association/trust),
but they are not visual evidence.

## Dated plan-amendment request (2026-10-29)

Requested from the owner/designing-architecture, not silently waived:

1. **AC2 wording.** An in-session `subagent` call is synchronous **for the
   parent model's turn**; the owner still interacts and the child runs in the
   background. The true non-blocking handle for the run-vehicle is
   `--detach` (pid/log/heartbeat/session file). Propose: state that AC2's
   handle is the `--detach` vehicle plus the in-session background tab, not a
   promise that the parent's tool call returns early.
2. **AC6 wording.** Routine milestones are capped at one per delegate per
   30 s; needs-input, stall, thrash and retry are deliberately immediate
   (AC7). Propose: "at most one *routine* synthetic message per 30 s;
   attention milestones fire once per distinct condition".
3. **AC13 residual.** Accept hermetic coverage for live loop/stall induction
   plus a non-TUI run-vehicle association proof (title row + loader/observer
   evidence), **or** fund a follow-up drill on a disposable shared service
   (managed service + TUI + `--server`) where a run-vehicle child and a
   SIGSTOP-induced stall can be observed. Until then RM-069 stays
   in-progress.
