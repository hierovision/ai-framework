# RM-076 — Consumer security hardening — Phase 3

> Detail file for roadmap row `RM-076`. Status and rank live in
> `docs/ROADMAP.md`; this file is provenance and design-pass input.

## Provenance

The consumer-security plan makes Phase 3 the continuous-detection gate: the next
sweep must be a repeatable operation rather than another manual audit. Phase 1
deferred the sweep, advisory snapshot, register, handoff checker, and weekly
`security.yml`. Its Open Question 16 resolved Phase 3 timing as a separate design
pass after Phase 1 lands.

RM-073 delivered Phase 1 through
[PR #144](https://github.com/hierovision/ai-framework/pull/144) on 2026-11-06, so
that design-pass trigger has fired. This row carries the plan's original
AC1–AC4 and AC11 together with the Phase 3 CI and posture scope. It does not
inherit Phase 1's acute credential-containment score.

## Scope

- A machine-readable inventory of exactly the five known slugs, exposed by
  `scripts/consumer_security_sweep.py --list`, including active/retired status.
- A deterministic offline sweep through
  `scripts/consumer_security_sweep.py`; identical audit fixtures produce
  byte-identical output and the offline path performs no network access.
- A separate, sanctioned advisory snapshot step through
  `scripts/fetch_advisories.py`, dry-run by default, with source, query, and
  `as_of` provenance and no manifest or lockfile mutation.
- A dated disposition register and `scripts/check_security_register.py`, with
  every reported finding covered exactly once by a fix, dated acceptance, or
  decommission disposition and an owner.
- The original AC11 handoff-completeness checker,
  `scripts/check_security_handoffs.py`. RM-075 owns the five briefs and their
  consumer remediation; this row owns their mechanical completeness gate.
- Per-repo dependency audit gates, Dependabot and secret-scanning posture, and
  the weekly `.github/workflows/security.yml` sweep with dated snapshot/report
  artifacts and no automatic PRs.
- Sanitized tracked security documentation; sensitive sweep material remains
  outside the public repository.

These are design-pass scope boundaries restated from the approved program plan,
not implementation acceptance criteria authored by this triage pass.

## Success measure

The next consumer-security sweep is a repeatable, CI-gated command with
byte-identical offline output and a complete disposition register.

## Exclusions

- No network access in the offline sweep; advisory retrieval remains a separate
  user-approved step.
- No Phase 2 consumer remediation or handoff authorship (RM-075), and no edits
  to consumer primary checkouts.
- No Phase 1 propagation-control rework (RM-073 is done).
- No automatic dependency fixes, `audit fix --force`, undated suppression, or
  automatic PR creation.
- No secret values in snapshots, reports, registers, or artifacts.
- No claim to enumerate unknown public consumers and no finite-sweep claim to
  prove the absence of every exposure.
- No new advisory-intake skill, runtime exploitation, penetration test, full
  OWASP/ASVS review, or legal/compliance conclusion.
