## What changed

- `scripts/opencode_v2.py` — the shared adapter (binary/version, service
  discovery, typed `/api/*`, `OPENCODE_DB` resolution, V2 DB readers, ordered
  permission rules, stream normalizer, denial classifier).
- Native V2 agent corpus (17 files): path-derived IDs, ordered `permissions`
  (`shell`/`subagent`/`edit`/`execute`), `execute: deny`, 1:1 shell allowlists.
- Dispatcher: `cwd`/`PWD` instead of `--dir`, always `--model` from V2
  discovery, `--session` preflight, shared-service default with
  `--standalone`/`--server`, `session.interrupt` on timeout, V2 denial
  classification.
- Wake: `session.get` → `session.agent` → `session.prompt`; 404 deferral.
- Watchdog/guard: `session_v2` + `session_message`, API-first liveness,
  `time_idle`/`idle_outcome` completion with a terminal-marker fallback.
- Eval/CI: `@opencode/cli@2.1.4`, `--standalone`, `OPENCODE_LOG_LEVEL=ERROR`,
  per-run `OPENCODE_DB`/XDG isolation, V2 tool vocabulary with logged V1
  aliases, continuation-loss restart.
- Operational gates: canary (C5-first), commit-bound consumer readiness,
  drained atomic cutover, post-smoke; V2 auto-compaction plugin.
- Docs: V2 reference, ADR-0014, active-doc sweep; Paragon native config +
  ten wrappers + its own checker.

## Migration residual (119 sessions) — classification

The rehearsal migrated 2,076 of 2,195 source sessions. The 119 absent IDs are
**not data loss**: the migration is a batched, resumable backfill ordered by
descending ID, and the rehearsal's smoke process exited before the tail
completed. The destination `kv.migration.v1-v2` row is
`{"phase":"sessions","cursor":"ses_0ad3c92a5ffecY1JU0nF4cXGew"}`; every one
of the 119 missing IDs is `id < cursor` and every one of the 2,075 source IDs
`id > cursor` is migrated. All 119 have V1 messages; a later boot resumes from
the cursor.

Machine-readable classification: `docs/opencode-v2-migration-classification.json`
(residual count, cursor, all-missing-below-cursor proof, source-untouched).
The canary's migration gate now records source-ID membership and the residual
count/IDs rather than claiming lossless migration. Cutover refuses an
unclassified residual; this record is the classification. No source row was
modified (`source_backup_sha256_after` equals the pre-copy hash).

## Operational design

- **C5 first:** the canary creates a consistent Python-`sqlite3` backup, config
  tarball, and dereferenced V1 agent snapshot, verifies hashes + integrity,
  and only then invokes V2. Every V2 process gets a scratch `OPENCODE_DB` and
  isolated XDG/TMP paths.
- **Consumer readiness:** `opencode_v2_consumer.py ready` writes both PR URLs
  and exact framework/consumer SHAs; the cutover refuses stale/missing/dirty/
  mismatched evidence.
- **Drain:** no live OpenCode/dispatch/observer/watchdog/guard process or
  service; fresh verified final V1 backup; explicit drain acknowledgement.
- **Switch:** one same-directory atomic rename of `$HOME/.yarn/bin/opencode`
  onto a wrapper that sets the versioned V2 `XDG_CONFIG_HOME`. V1 package,
  config, agents, and plugin stay untouched.
- **Post-smoke before merge:** default-is-V2, agent/wrapper load, config,
  credentials, plugin, `session_v2`, live drills; a failure routes to
  rollback.
- **Rollback:** preserve the failed V2 DB, restore the final V1 DB, restore
  the original link, repair mismatched V1 agent files from the snapshot, and
  prove a V1 session read.
