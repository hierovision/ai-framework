# RM-075 — Consumer security hardening — Phase 2

> Detail file for roadmap row `RM-075`. Status and rank live in
> `docs/ROADMAP.md`; this file is provenance and design-pass input.

## Provenance

The 2026-10-25 consumer-security program split remediation by ownership. Phase 0
contained the live credentials and closed on 2026-11-06. Phase 1 delivered the
framework propagation controls as RM-073 through
[PR #144](https://github.com/hierovision/ai-framework/pull/144). RM-073 is done;
its detail explicitly defers Phase 2 consumer remediation and handoff briefs.

This row carries that deferred Phase 2 work. Its trigger fired when Phase 1
landed. The remaining consumer exposures still span the known fleet, but they do
not retain Phase 1's acute live-credential urgency.

## Scope

- One disposition pass for each known consumer: `excel-daily-monitor`,
  `marvin-slack`, `pln` (retired and archived; decommission-only),
  `pt`/`phasetimer`, and `paragon-learning-network`.
- One handoff brief per repo carrying the P0/P1 findings, exact installed and
  fixed versions, commands, verification, and owner actions. The briefs retain
  the plan's prohibition on `audit fix --force` and undated suppressions.
- Every pass runs under `reference/cross-repo-isolation.md`: an isolated
  worktree at the required ref, never the consumer's primary checkout.
- Every exposure ends fixed, explicitly accepted with a date, or decommissioned.
  Each pass leaves a verification record in its own repo or handoff.
- The framework repo coordinates and verifies the handoffs; it does not edit the
  consumer repos as part of this row.

The per-consumer design and execution passes own the exact remediation steps.
This row does not pre-empt those passes with implementation acceptance criteria.

## Success measure

Every known consumer's exposure is fixed, dated-accepted, or decommissioned, and
each of the five isolated per-repo passes leaves a verification record.

## Exclusions

- No edits to a consumer's primary checkout and no consumer changes authored
  from the framework checkout.
- No reading or rotation of secret values; owner-controlled containment remains
  separate from the handoff.
- No Phase 1 rework and no Phase 3 sweep, advisory, register, or weekly CI
  tooling (RM-076).
- No claim to enumerate unknown public consumers.
- No runtime exploitation, penetration test, full OWASP/ASVS review, or
  legal/compliance conclusion.
- No full RM-008 agent permission matrix and no RM-015 tagged-worktree install.
