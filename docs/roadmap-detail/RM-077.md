# RM-077 — Supported OpenCode upgrade shadow repair and truthful verification

> Detail file for roadmap row `RM-077`. Status and rank live in

framework host. The release and canary were healthy; the default `opencode`
command was not. Design and approval: plan
`.opencode/plans/rm-077-opencode-upgrade-shadow.md` (approved 2026-11-09;
retired at merge per ADR-0008/AGENTS rule 4). Decision record: ADR-0017

**Status: done** (2026-11-09). Delivered on branch

## Defect (observed 2026-11-09)

`@opencode/cli@2.2.6` installed successfully and `opencode2 --version`
returned `opencode v2.2.6`, but `scripts/opencode_upgrade.py upgrade --to
2.2.6 --apply --drain-acknowledged` reported a failed smoke:

```text
verify binary: FAIL 1.19.4
verify api: FAIL
verify plugin: FAIL loader did not load ...
verify observer: FAIL api unavailable
```

An explicit 2.2.6 probe passed (`opencode2 debug paths config`,
`/api/info` version, agent list, plugin loader), so the release was healthy
and the default command was the defect.

## Root cause

Yarn-global retained both `@opencode/cli` and `opencode-ai`; both publish an
`opencode` bin. Yarn linked `opencode2` to V2 but `opencode` to V1, and the
orchestrator assumed its post-install `PATH` lookup still resolved V2. The
failure path also claimed a rollback it did not perform (neither package nor
config/DB was restored), and `status` recommended re-staging a config that was
already supported.

## Requirements (AC1–AC10 of the approved plan)

1. Yarn relink is reproduced hermetically: a V2 `opencode2`, a V1 `opencode`,
   and an official-install stub that rewrites the default link; apply exits 0
   only after repairing to V2 and smoking V2.
2. The repaired binary is the one verified: the smoke receives an explicit
   repaired link and asserts its exact version.
3. Already-installed recovery is idempotent through the CLI: skip the official
   install, repair the shadow, verify, record `applied`.
4. A failed apply is truthful: `verified: false`, `rolled_back: false`, named
   failure stage, target package and default-link evidence, backup path, and
   state at `prepared`.
5. Link repair fails closed: missing/mismatched target binaries or a
   config-root mismatch fail before smoke and never link an unverified
   executable.
6. `status`/`doctor` diagnose the shadow: target package, default version,
   `shadow_ok`, and the exact repair command; no re-staging of a supported
   config.
7. No false rollback claim remains in code, tests, README, reference, or the
   RM-071 detail.
8. The corrective path is documented and executable in README, the reference,
   and the dated ADR-0017 amendment.
9. The current 2.2.6 install is repaired without reinstall (owner-run after
   merge).
10. No canary gate, post-smoke check, pin seam, or assertion is deleted or
    relaxed; the retained V1 package and no custom wrapper remain.

## Bounded closure (final implementation round, 2026-11-09)

- **M1 — prepare is exception-safe.** `prepare()` wraps seam/plugin writes,
  npm install, ADR append, verification, and lockfile delta. A failure writes a
  durable `prepare-<target>-failure.json` (stage, exception, completed actions,
  restored/lockfile lists, restore guidance), restores the files written in this

## Owner repair after merge

The 2.2.6 host repair is owner-run from a normal terminal with all sessions
closed; the sequence is **canary -> apply -> verify**. Fresh hardened canary
evidence is required; legacy evidence without `zero_migration`/`target_only_ids`
is refused, so regenerate it first:

```sh
python3 scripts/opencode_upgrade.py canary --to 2.2.6
python3 scripts/opencode_upgrade.py upgrade --to 2.2.6 --apply \
  --drain-acknowledged --stop-service
python3 scripts/opencode_upgrade.py status
python3 scripts/opencode_upgrade.py doctor
```

The pre-existing failed `upgrade-2.2.6-verify.json` is automatically archived
byte-identically as `upgrade-2.2.6-verify.json.failed-<UTC stamp>` (an
unverified predecessor; a verified one would use `.previous-<UTC stamp>`)
before the new evidence is written. Existing DB backups created before the 0600
fix get the one-time owner chmod from the repo root:
`chmod 600 ~/.config/opencode.v1-backup-*/opencode.db
"$PWD"/.scratch/opencode-v2/pre-upgrade-*/opencode.db 2>/dev/null`.

Expected: `opencode --version` and `opencode2 --version` both print
`opencode v2.2.6`, `opencode debug paths config` is
`~/.config/opencode`, `upgrade-2.2.6-verify.json` has `verified: true`, and
`upgrade-state.json` is `applied`.
