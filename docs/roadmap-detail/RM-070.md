# RM-070 — Attention milestones start one parent turn (bounded)

> Detail file for roadmap row `RM-070`. Status and rank live in
> `docs/ROADMAP.md`; this file is provenance.

Source: owner challenge 2026-10-31. RM-069 shipped the observer with every
milestone `resume:false`, so a `thrash`, `stall`, `needs-input` or `denied`
condition reached an idle parent's inbox without starting a turn; the child
could burn work or deadlock before the parent's next turn. The owner accepted
option 1: attention wakes the parent once per condition; routine progress stays
quiet. Decision record: ADR-0015 → *Amendment (2026-10-31)*.

**Status: done** (2026-10-31). Delivered on branch
`feat/rm-070-attention-wake`; PR opened unmerged. The approved plan was retired
per ADR-0008/AGENTS rule 4 — its essence lives in ADR-0015, the RM-069 detail
amendment, `reference/subagent-supervision.md` §7, the observer README and
this file.

## Requirements (AC1–AC10 of the approved plan)

1. One wake per condition: `thrash`, `stall`, `needs-input`, `denied` start
   exactly one parent turn; a re-delivered condition starts none.
2. Routine (`start`, `first-tool`, `resume`) and `terminal` stay
   `resume:false`; the RM-058 terminal wake remains the only terminal prompt.
3. Bounded: `maxAttentionWakes` (default 3) per child per observer process.
   Over the cap the milestone is still queued as context and the drop is
   logged with a count.
4. No wakes for history: stale, archived, unknown and store-terminal rows emit
   no milestone and therefore no wake.
5. Same trust gate: only a trusted root in the same directory receives a wake;
   an untrusted/unresolvable parent records the existing degradation.
6. Honest text: a wake names child, condition and task, says the parent may
   steer or interrupt, and never claims the child stopped.
7. Configurable: `attentionWake` (default true) and `maxAttentionWakes`
   (default 3), options and env (`DELEGATION_OBSERVER_ATTENTION_WAKE`,
   `DELEGATION_OBSERVER_MAX_ATTENTION_WAKES`), options winning.
8. Red-first unit tests for every case, plus mutation guards.
9. Live proof on a disposable isolated service: a thrashing child and a
   needs-input child each start one parent turn; archive captures.
10. Docs and board: ADR amendment, RM-069 detail amendment, observer README,
    supervision reference, this row/detail, PR body.

## Delivered

- **Reducer policy (`plugins/delegation-observer/state.ts`).**
  `ObserverConfig` gains `attentionWake` (default true) and
  `maxAttentionWakes` (default 3); `Delegate` gains `attentionWakes`.
  `Milestone` gains `wake: boolean`. `WAKE_KINDS` is exactly
  `thrash | stall | needs-input | denied`. `milestone()` marks `wake:true`
  only for those kinds when the policy is enabled and the per-child budget has
  room, and increments the budget when it does. The same condition never
  reaches the marking twice (existing per-condition dedupe). Retry stays an
  attention strip alert but never wakes. Routine and terminal are always
  `wake:false`.
- **Config seam.** `envConfig()` parses the two new env values; `tuiConfig()`
  merges them per key (forwarded option > env > default), and the server merges
  `DEFAULTS < env < ctx.options.delegationObserver < startObserver options`.
- **Server (`plugins/delegation-observer/server.ts`).** Sends
  `resume: Boolean(m.wake)` with `delivery:"steer"`; the existing trusted-root
  and same-directory gates are unchanged. An attention milestone without a
  wake is logged as `attention wake dropped` with `reason` (`cap` or
  `disabled`), `attentionWakes` and `maxAttentionWakes`. Synthetic metadata
  carries `attention` and `wake` for post-hoc evidence.
- **Host event ingestion.** The live drill found the headless 2.1.4 server
  emits `session.tool.input.started` (name) and `session.tool.input.ended`
  (input JSON) but no `session.message.content.updated`; `session.tool.called`
  carries no name. The reducer consumes the input pair (and still accepts
  content updates), and `toolTarget` treats `input.code` as a target for the
  build agent's Code Mode `execute` tool. Without this, thrash never fired
  headless — a real gap the drill exposed.
- **Honest wake text.** `attentionText()` builds
  `<agent> <session> <condition>: <detail>. Task: <task>. The parent may steer
  or interrupt the child; check its current state first.` No stopped/dead claim.

## Known limits (tracked, not waived)

- Each attention incident can cost one parent turn. Per-condition dedupe and
  the cap bound it; the terminal wake is unchanged.
- A parent that ignores a wake gets no repeat for that condition — deliberate:
  repeated wakes would multiply spend without adding information.
- A needs-input wake can arrive while the owner is already answering in the
  TUI; the wake text says to check the child state first, and the plugin never
  auto-answers or interrupts.
- `retry` remains attention for the strip but does not wake (it is a vendor
  transition, not an owner decision).
- Wake delivery uses the existing root/location gate; a wake dropped for an
  untrusted parent still consumes its per-child budget (the budget is charged
  when the reducer emits, conservative by design).
- The plugin still needs the versioned corpus refresh + restart to take effect
  on the live host.
